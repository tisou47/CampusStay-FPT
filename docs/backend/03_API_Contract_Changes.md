## 2. Breaking changes

| ID | Change | Why | Backend | Web | Mobile |
|---|---|---|---|---|---|
| B-01 | `GET /check-out/{studentCode}` and `POST /check-out/{studentCode}` become `/check-out/{allocationId}`; items of `GET /check-out` gain `allocationId`. | A student code in the URL ends up in proxy logs and browser history (personal data, Law 91/2025/QH15). An Allocation id also stays unique if the same student checks out of two Terms. | Pending (S4) | Done: Check-out desk selects and calls by `allocationId` | — |
| B-02 | `POST /auth/sign-in { username, password, remember }` becomes `{ email, password, remember }`; `remember` is optional (default `false`). | ADR-13: CampusStay keeps its own passwords; it cannot check FPT Wi-Fi credentials. To be confirmed with the mentor (OI-14). | Done | Done: Email field, error texts, `VITE_PASSWORD_RESET_URL` removed | Pending |
| B-03 | IDs are JSON **strings**: every field named `id` or ending in `Id`, at any depth (`"id": "42"`, `"roomTypeId": "3"`). Request bodies and URL parameters send them as strings; the server also accepts numbers. Amounts, counts and rates stay numbers. Replaces C-01. | ADR-15: URL parameters, `<select>` values and browser storage are strings, so clients compare IDs without conversion. | Done for every coded endpoint (`user.id`, `GET /terms`); each new endpoint follows the rule | — (already compares strings) | Pending: model IDs as `String` |

| C-21 | Review and assignment (S3) | **Scope.** An Application has no Bed before assignment, so it belongs to the Blocks of its student's gender (a Block houses one gender); Staff and Managers see and decide only those (`403 BLOCK_OUT_OF_SCOPE`). `GET /applications/{id}` is the same path for the student and the back office: Staff/Manager get the back-office view, and opening a Submitted Application moves it to Under Review. **Review.** `decision` is `Approved` or `Rejected` (case-insensitive); `note` is required to reject (`400`, `details.fields.note`); a rejected paid Deposit is refunded by the active refund rule and the student is notified with the note. `POST /applications/{id}/review` → `204`; `POST /applications/bulk-review` approves only (`{ approved, skipped }`: Applications that are not Submitted/Under Review, out of scope or no longer eligible are skipped). `409 ALREADY_DECIDED`. **Runs.** A run id is `RUN-<n>`; `POST /assignment-runs` → `{ id }`, `termId` required. A final run replaces the proposal still in review (`409 RUN_PARTLY_COMMITTED` once a Block of it is committed); a dry run never changes anything (`409 DRY_RUN` on resolve/commit). `fit` is 0–100; `score` (rooms) and `averageScore` (approval) are fractions 0–1. `issue.tone` is info·warning·error; LOW_FIT (info) does not block. **Conflicts.** `options[].key` is `KEEP`, `SOLO`, `CLASS:<roomClassId>` or `TYPE:<roomTypeId>:<roomClassId>`; a Not eligible student has no option but the waitlist. `resolve` → `{ applicationId, bed, resolved, waitlisted }`; `409 NO_BED_LEFT`, `409 BLOCK_SUBMITTED`, `409 RUN_CLOSED`. **Commit and approval.** `commit { block }` is Staff sending the Block to its Manager → `204` (`409 CONFLICTS_LEFT` while a blocking conflict is open). The Manager's `approve { block }` → `{ allocated, waitlisted }` creates the Allocations, the Balance Invoices (due after Admin › Fees `balanceDays`) and the "Your room is ready" notifications in one transaction; waitlisted Applications become Waitlisted (Round 2). `return { block, comment }` → `204`. `409 NOT_SUBMITTED`. **My Room.** `GET /students/me/allocation`: `term` is `{ id, name, stayStart, stayEnd, resultsPublishedAt }`; `room` is the Room code (`A-305`) and `bed` the Bed label (`B`); `allocation.status` is Allocated or Checked in; `rulesUrl` is null (the Block's house rules come with S5). Admin › Matching Criteria › dry run now runs the engine over the Term's approved Applications. | Nothing to change |
| C-22 | Staff payments (S3) | `GET /payments` lists the Invoices of the Blocks in scope: an Invoice issued once the student holds a Bed belongs to that Block, a Deposit to the Blocks of the student's gender (C-21). Filters: `type` = an Invoice type (`deposit`, `balance` …); `status` = labels, comma-separated (Void is hidden unless asked for); `method` = VietQR or Manual transfer; `date` = `today`·`7d`·`term` (default), on the paid time, else the issue time; another value → `400` naming the field. `reference` is the bank reference (SePay's, or the one Staff typed). `summary` counts the whole Term and Blocks, not the filters: `collectedToday` (VND) and `collectedTodayCount` are Payments since 00:00 campus time; `depositsSubmitted` counts Deposits that are not Void. `POST /payments/{invoiceId}/confirm` (multipart `amount`, `reference`, optional `receipt` JPEG/PNG/PDF ≤ 5 MB) → `204`; it settles the Invoice like a VietQR Payment (a Deposit submits the Application). `amount` must equal the Invoice amount; errors `400 VALIDATION_FAILED` (`amount`, `reference`), `400 FILE_TYPE_NOT_ALLOWED`, `409 ALREADY_PAID`, `409 INVOICE_NOT_PAYABLE`, `409 MANUAL_CONFIRM_OFF` (Admin › Fees). An Invoice outside the user's scope answers `404`. Staff and Managers may open `GET /invoices/{id}` of their Blocks. `receipt.url` is a signed link (A-10). | Nothing to change |
| C-23 | Check-in and Check-out desk (S4) | **Balance.** From S4 the Balance Invoice also holds the Utility Deposit (Admin › Utility: estimate × months held), as the line "Utility Deposit (held until check-out)" and in `utilityDeposit`. **Check-in.** Without `termId` the current Term. `lookup?q` takes a student code, a name (case- and accent-insensitive; several matches → `409 MANY_MATCHES`, type the code) or the pass `CSTAY-PASS:<allocationId>` (A-11). A student outside the user's Blocks answers `student: null`; `not-allocated` only for a student of a gender the user's Blocks house. `checks`: Bed allocated, Balance paid, Utility Deposit paid, inside the Term's check-in window (or an approved late check-in); any failed check → `status: blocked` and `owes` = the unpaid Balance split into its Term-price part and the Utility Deposit. `room` is the Room code, `bed` the Bed label, `block` "Block A". `POST /check-in`: `items` are labels of the hand-over list (case-insensitive; another value → `400`, `details.fields.items`); errors `409 CHECK_IN_BLOCKED` (the message names the failed checks), `409 ALREADY_CHECKED_IN`, `404` (no Bed). `today.block` is the Block code when one Block is selected, else null; `recent` holds today's last 8 check-ins (`bed` = Bed code). **Check-out.** The list holds the Term's checked-in Allocations and those already checked out; `status` Pending, Draft or Checked out; `reason` defaults to End of Term; `bed` is the Bed label. Settlement: `held` = the Utility Deposit paid with the Balance; `share` = the Room's consumption since its last reading (a monthly reading or one taken when residents changed) × Admin prices, split between the residents checked in, rounded by the Admin rule; `periodLabel` "since dd/mm/yyyy", null without an earlier reading (share 0); `unpaid` = unpaid utility Invoices, settled from the deposit; `refund` = held − share − unpaid − damage. `draft: true` saves the readings and returns the estimate; confirming needs `keyReturned: true` (`400`) and a reading not below the last one (`400`, named field), records the reading, ends the Allocation (the Bed is free) and keeps the settled figures.
